## 二、你还需要做的三件事

### 第 1 件：部署中转服务（目前还没做）

电脑端是「往外连」，所以中转服务必须在公网有地址。需要：一台云服务器 + 一个**已备案的域名** + HTTPS 证书。

服务器上（relay_server.py 零依赖，只用 Python 标准库）：

    mkdir -p /opt/rice-relay && cd /opt/rice-relay
    # 把 relay_server.py 传上去
    export RELAY_TOKEN='自己设一个口令'
    nohup python3 relay_server.py 9000 > relay.log 2>&1 &

再挂 Nginx + HTTPS —— deploy/ 目录里有现成的：nginx-rice-relay.conf、rice-relay.service、install.sh。

> ⚠️ **必须 https**：微信正式版不允许 http，也不允许直接用 IP。域名必须 ICP 备案。
> **小程序备案 ≠ 域名备案**，这两个是分开的，先确认域名备案状态。

### 第 2 件：小程序接入（拷一个文件 + 加三行）

1. 把 miniprogram/utils/relay.js 拷进你的小程序项目（放到 utils/relay.js）
2. 在**识别完成**的地方加：

    const relay = require('../../utils/relay.js');
    relay.setBase('https://你的中转域名');

    relay.locate().catch(() => null).then(loc => relay.sendToPc({
      filePath: tempFilePath,        // 拍照/选图的临时路径
      label: '稻瘟病',               // ← 你小程序里已经算出来的识别结果
      score: 0.88,
      boxes: 2,
      model: 'yolov8n-onnx',
      lat: loc && loc.lat, lng: loc && loc.lng,
      note: '东片1号田',
    }))

> **关键**：识别结论必须传给 sendToPc 的 label / score。
> 它内部走的是**第三步 finish** —— 中转服务的 create 接口白名单里**没有** label/score，
> 只有 finish 才收。手动拼请求的话，别把结论放在第一步。

### 第 3 件：微信后台两处配置（不做会直接失败）

| 位置 | 做什么 | 不做会怎样 |
|---|---|---|
| 开发管理 → 开发设置 → 服务器域名 | request 和 uploadFile 合法域名都加你的中转域名 | 正式版请求被直接拦截 |
| 设置 → 服务内容声明 → 用户隐私保护指引 | 声明**地理位置**用途 | wx.getLocation 报 appid隐私受限 |

> 你的小程序**已经上线**，所以加定位不能直接发版：先补隐私声明、等审核通过，再提代码。

## 三、电脑端怎么配

程序 →「自动巡检 → 云端同步」→ 填中转地址和口令（口令 = 服务器上的 RELAY_TOKEN）→ 点同步。
图和结论一起进收件箱，随后自动巡检照常检测、复核、落库、地图落点。

配置存进 config.json 的 relay_base / relay_token，下次不用重填。

## 五、症状对照表

| 现象 | 原因 |
|---|---|
| 同步时报「连不上中转服务」 | 地址写错 / 服务没起 / 服务器防火墙没开端口 |
| 报 HTTP 401 | 电脑端口令和服务端 RELAY_TOKEN 不一致 |
| 拉到图但**手机结论是空的** | 小程序只调了 create+upload，**没调 finish**（最常见） |
| 小程序报 getLocation:fail appid隐私受限 | 没在后台声明地理位置用途 |
| 小程序请求被拦 | 合法域名没配，或域名不是 https / 没备案 |
| 同步一直 0 条 | since 已推进到最新；要重来在电脑端用「重置」重新拉 |
